# VK Trigger Bot

Бот-воронка для сообщества VK: отслеживает новые комментарии под записями сообщества и отправляет PDF в личные сообщения подписчику, который написал триггер-слово.

## Как работает сценарий

1. Бот получает событие `wall_reply_new` через Bots Long Poll API.
2. Обрабатываются только комментарии пользователей на стене настроенного сообщества.
3. Текст комментария нормализуется: Unicode NFKC -> `strip()` -> `toLowerCase(Locale.ROOT)`.
4. После точного совпадения с `VK_TRIGGER_WORD` бот вызывает `groups.isMember`.
5. Если автор состоит в сообществе, бот отправляет ему текст и PDF в личные сообщения.
6. Если автор не состоит в сообществе, бот отправляет ему сообщение `VK_NON_MEMBER_TEXT` без файла и запоминает ожидающую заявку.
7. После события `group_join` бот автоматически отправляет PDF с коротким текстом `VK_AFTER_SUBSCRIPTION_TEXT`, без повторного приветствия. Повторно писать «сила» не нужно.
8. Если этому пользователю файл уже отправлялся, бот один раз отвечает текстом `VK_ALREADY_SENT_TEXT`, а следующие повторы подавляет на время `VK_REPEAT_REPLY_COOLDOWN`.

Значение триггера по умолчанию — `сила`.

Примеры:

- `сила` -> сработает;
- `СИЛА` -> сработает;
- `  СиЛа  ` -> сработает;
- `сила!` -> не сработает;
- `пришли силу` -> не сработает.

Требуется точное совпадение всего комментария после нормализации. Это не поиск подстроки и не морфологический поиск.

## Защита от повторов

- PDF отправляется пользователю не более одного раза за время работы экземпляра приложения.
- Сообщение с просьбой подписаться отправляется неподписанному пользователю не чаще одного раза за `VK_REPEAT_REPLY_COOLDOWN`.
- Событие подписки обрабатывается только для пользователя с ожидающей заявкой; обычным новым подписчикам файл не рассылается.
- Первая новая попытка после отправки PDF получает сообщение «файл уже отправлен».
- Дальнейшие попытки того же пользователя во время cooldown не вызывают ни проверку подписки, ни отправку сообщения.
- Повторно доставленное VK событие с тем же `owner_id + post_id + comment_id` игнорируется.
- Кэш обработанных комментариев ограничен последними 10 000 записями.
- `random_id` вычисляется детерминированно из сообщества, пользователя, комментария и вида ответа.

Состояние, включая список пользователей, ожидающих подписки, хранится в памяти. Если приложение перезапустить между комментарием и подпиской пользователя, автоматическая выдача для этой заявки потеряется. Для сохранения истории между перезапусками или запуска нескольких экземпляров нужен общий storage, например PostgreSQL или Redis.

## Стек

- Java 21
- Maven
- Spring Boot 3.5.x
- Spring `RestClient`
- Jackson
- VK API 5.199
- Bots Long Poll API

VK API вызывается напрямую по HTTP, без сторонней библиотеки для ботов.

## Настройка сообщества VK

В настройках сообщества:

1. Включите сообщения сообщества.
2. Создайте access token сообщества с правами, необходимыми для сообщений и документов.
3. В разделе Long Poll API включите Long Poll.
4. В типах событий включите **добавление нового комментария на стене** (`wall_reply_new`).
5. Включите **Пользователи → Подписка на сообщество** (`group_join`).
6. Скопируйте ID сообщества и token.

Важно: VK разрешает сообществу отправить личное сообщение только пользователю, который разрешил сообщения от сообщества. Подписка сама по себе не всегда предоставляет это разрешение. Если личные сообщения закрыты, VK API отклонит отправку — обойти это ограничение средствами бота нельзя.

## Конфигурация

Обязательная переменная:

```bash
export VK_GROUP_TOKEN='...'
```

ID сообщества `235381622` уже задан в `application.yml`. При необходимости его можно переопределить переменной `VK_GROUP_ID`.

Опциональные переменные:

```bash
export VK_TRIGGER_WORD='сила'
export VK_GROUP_ID='235381622'
export VK_REPLY_TEXT='Привет! Вот твой файл 👋'
export VK_ALREADY_SENT_TEXT='Файл уже был отправлен вам ранее.'
export VK_NON_MEMBER_TEXT='Привет, хочу отправить тебе материал "Где мои силы?", но у тебя нет подписки. Чтобы получить, подпишись на моё сообщество.'
export VK_AFTER_SUBSCRIPTION_TEXT='Вот твой файл'
export VK_REPEAT_REPLY_COOLDOWN='PT1M'
export VK_API_VERSION='5.199'
export VK_RETRY_DELAY='PT3S'
```

Никогда не записывайте `VK_GROUP_TOKEN` в `application.yml`, исходный код или Git. Передавайте ключ только через переменную окружения или Environment Variables конфигурации запуска IDE. Если ключ был опубликован, его необходимо отозвать и создать заново.

Значения времени задаются в формате ISO-8601 Duration: `PT30S` — 30 секунд, `PT1M` — 1 минута, `PT1H` — 1 час. Значение `PT0S` у `VK_REPEAT_REPLY_COOLDOWN` разрешает отвечать на каждый повтор.

## PDF

Замените файл:

```text
src/main/resources/files/presentation.pdf
```

на нужный PDF с тем же именем. Либо укажите другой Spring resource:

При первой выдаче бот загружает PDF на сервер VK, поэтому большой файл может отправляться не мгновенно. В текущем процессе полученный идентификатор документа кэшируется и повторно используется для следующих пользователей. Сетевые операции ограничены таймаутом: вместо бесконечного ожидания причина будет записана в лог.

```bash
export VK_PDF_PATH='file:/opt/vk-bot/my-Где_мои_силы_—_Анастасия_Гулина_психолог_КПТ.pdf'
```

При запуске приложение проверяет наличие файла, доступность для чтения и сигнатуру `%PDF-`.

## Локальный запуск

Нужны Java 21 и Maven 3.6.3+.

```bash
mvn clean test
mvn spring-boot:run
```

Mockito подключается к JVM тестов как явный `-javaagent` через Maven Surefire. Это устраняет предупреждение о динамической загрузке agent на новых версиях JDK.

Если после изменения зависимостей приложение ранее запускалось из IDE, выполните `mvn clean package` и полностью перезапустите процесс. Загрузка PDF использует multipart и требует runtime-зависимость `org.reactivestreams:reactive-streams`, уже указанную в `pom.xml`.

Для запросов к upload-серверам VK используется Apache HttpClient 5 с классическим HTTP/1.1-транспортом. Если VK возвращает `pu.vk.com`, бот подключается по TLS через доступный домен `pu.vk.ru`, но сохраняет исходный HTTP `Host`, путь и параметры временной upload-ссылки. Автоматические повторы POST и cookies клиента отключены. Временные ответы upload-сервера `405` и `no_file` повторяются внутри одной обработки с получением новой upload-ссылки, без трёхсекундного повтора всего Long Poll-события.

После подключения Long Poll приложение пишет безопасные диагностические строки `Received VK update` и `Received wall comment`. Они показывают тип события, ID объектов и результат сравнения с триггером, но не содержат текст комментария или токен.

Healthcheck:

```text
GET http://localhost:8080/actuator/health
```

## Docker

Во время сборки Docker запускаются тесты.

```bash
docker build -t vk-trigger-bot .

docker run --rm \
  -e VK_GROUP_TOKEN='...' \
  -e VK_GROUP_ID='235381622' \
  -e VK_TRIGGER_WORD='сила' \
  -p 8080:8080 \
  vk-trigger-bot
```

### Развертывание на BotHost

Проект разворачивается на BotHost через собственный `Dockerfile`, поэтому значение языка в форме не определяет Java runtime. В форме создания бота:

1. выберите платформу `VK`;
2. включите «Использовать собственный Dockerfile»;
3. оставьте «Главный файл» пустым;
4. для Bots Long Poll отключите «Использовать домен»;
5. используйте одну replica.

Добавьте в форме отдельными парами «ключ — значение»:

```text
VK_GROUP_TOKEN = <токен сообщества>
VK_GROUP_ID = 235381622
VK_API_VERSION = 5.199
VK_TRIGGER_WORD = сила
```

Кавычки в значениях не нужны. `PORT` задаётся платформой и читается приложением через `${PORT:8080}`. JAR внутри Docker-образа расположен в `/opt/vk-trigger-bot`, а не в `/app`: BotHost монтирует исходники репозитория в `/app`, поэтому артефакты сборки нельзя хранить в этом каталоге.

## Как отправляется PDF

При первой успешной обработке триггера пользователя приложение:

1. проверяет подписку методом `groups.isMember`;
2. вызывает `docs.getMessagesUploadServer`;
3. загружает PDF multipart-запросом в поле `file`;
4. вызывает `docs.save`;
5. собирает attachment вида `doc{owner_id}_{id}_{access_key}`;
6. вызывает `messages.send`.

Если загрузка PDF уже прошла, но отправка сообщения временно завершилась ошибкой, полученный attachment остаётся в памяти и повторно не загружается.

## Ограничение deployment

Запускайте текущую реализацию в **1 replica**. Bots Long Poll и локальное состояние подходят для одного небольшого worker-процесса. Для нескольких replicas, HA и сохранения истории между перезапусками следует перейти на Callback API и общий storage.
